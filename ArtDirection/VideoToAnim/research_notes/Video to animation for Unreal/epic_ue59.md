## Q1 (Part A). What is physically installed in UE 5.9 on this machine that relates to video / mocap / capture / pose / MetaHuman Animator?

### Takeaway
UE 5.9 ships the full MetaHuman Animator (MHA) editor stack including a built-in **mono-video face solve**, the Capture Manager / Live Link Hub **Mono Video Ingest** path, and a **body-tracker plug-in interface**, but it does NOT ship any body solver. ## Q4 (Part B). What can MetaHuman Animator do from ordinary (non-iPhone, non-depth) video today? Requirements, caveats, local vs cloud, face vs body

### Takeaway
Face: yes, mono video from any camera works and is built into MHA since UE 5.6 (offline and real-time), no iPhone/depth/Identity needed. Body: yes since UE 5.8, but only via the free, **experimental**, **Windows-only** Fab plugin "MetaHuman Animator Markerless Motion Capture" (UE 5.8-5.9), single actor from a single camera, processed locally and offline, with Epic's own guidelines demanding a static camera, a full-body view of one performer, and form-fitting clothes. No independent quality measurements exist yet.

### Cited Findings
**Face from mono video**
- MetaHuman 5.6 (forum post 3 June 2025): MHA can "solve facial animation in real time from a much wider range of single-camera devices", sources include "single-camera data sources (including webcams), mobile devices, or audio input"; Live Link Hub is used to ingest performance data for offline solves; the depth path needs the Depth Processing plugin — VERIFIED [MetaHuman 5.6 Release](https://forums.unrealengine.com/t/metahuman-5-6-release/2539165) (Epic post by JamesPullan).
- Offline: Performance asset, Input Type "Monocular Footage"; face solve needs no Identity (local `GenerateAnimationFromFootage` comment; Python script above) — VERIFIED. Face models: Face Detector, Head Pose Tracker, Face Solver (Generic Rig Solver; "Small Face Detector/Solver" appear when the body plugin is enabled and are default when Body Tracking is on) — VERIFIED [Process and Export](https://dev.epicgames.com/documentation/metahuman/metahuman-animator-02-process-and-export-your-animation-in-unreal-engine).
- Webcam rule: any USB video capture device supported by the Windows Universal Video Class (UVC) driver can be used (paraphrase); a software virtual camera needs Windows 11; auto-focus/exposure should be disabled — VERIFIED [Capture Device Requirements](https://dev.epicgames.com/documentation/metahuman/metahuman-animator-capture-device-requirements). Real-time Android face needs Snapdragon 8 Gen 1+/Tensor G3+ — same page.
- Platforms: real-time animation from mono video or audio is Windows and macOS only; the plugin for body is Windows only — VERIFIED [Hardware Requirements](https://dev.epicgames.com/documentation/metahuman/metahuman-hardware-requirements-in-unreal-engine). MHA 5.8 notes: offline and real-time facial MHA on Linux and macOS, "Editor-only solution; not a runtime or player-facing feature" (fetch summary of [5.8 notes](https://dev.epicgames.com/documentation/metahuman/metahuman-5-8-release-notes-in-unreal-engine)) — VERIFIED via fetch; wording from a page summariser.

**Body from mono video**
- Epic's doc: full-character animation for a MetaHuman is generated in Unreal from standard video footage such as a webcam (paraphrase); you can "capture body, or both body and face performance from a single camera"; the plugin "removes the requirement for a mocap rig, helmet camera, or markers"; batch processing runs "locally on your machine" — VERIFIED [Animation from Mono Video Capture](https://dev.epicgames.com/documentation/metahuman/metahuman-animation-from-mono-video-capture-in-unreal-engine) (browser read; page links are the 5.8 doc set).
- Status: "Experimental features are not production-ready and may change or be removed in future releases." "The plugin is available only on Windows for body or face and body capture." Prereqs: UE 5.8 or later, MHA plugin, Live Link Hub + Capture Manager Editor plugins, the Fab plugin, takes from a mono camera or Live Link Face (iOS or Android) — same page, VERIFIED.
- Two capture paths: single camera (face and body solved independently on the same footage) or dual camera (e.g. helmet cam for face + off-actor camera for body, combined in a level sequence); with a MetaHuman identity stand-in "all MetaHumans share the same skeleton" so it maps without retargeting — same page, VERIFIED.
- Fab listing (Epic Games, free, "Standard License", published June 17 2026, last update **November 9, 2026**, UE versions **5.8 – 5.9**, Windows only, "Contains third party software usage: Yes", "This is an Experimental release", category Tools & Plugins / Engine Tools, "Allows usage with AI: No"): markerless body capture producing full-body animation including hands from video, able to drive the MetaHuman skeleton directly or be retargeted to other character types (paraphrase); "Runs entirely on your own machine—no cloud, no credits"; face+body from one source or body paired with face footage from a separate camera; Python/Blueprint automation — VERIFIED [Fab listing](https://www.fab.com/listings/4095b8e0-3eff-44f1-acb4-cb40b99228b9) (rendered in browser; changelog entries say "No notes provided").
- Body workflow: ingest in Live Link Hub (Tools > Live Link Hub > Capture Manager > Data Devices > Add > Mono Video Ingest; set source path; Add to Queue; Start; assets land in `Content/CaptureManager/Imports`); create MetaHuman Performance, pick footage; body only = uncheck Facial Tracking, check Body Tracking, set Head Movement Mode to Disable (paraphrase); for face+body set Small Face Detector and Small Face Solver (enable Show Engine Content if missing); Process; Export Animation with either "Existing Skeleton" (retargeting applied automatically; target = assembled MetaHuman skeletal mesh) or "Performer Skeleton" (new skeletal mesh from the actor's proportions, for retargeting to non-MetaHuman characters) — VERIFIED [01 Import](https://dev.epicgames.com/documentation/metahuman/metahuman-animator-01-import-your-footage-in-unreal-engine) and [02 Process and Export](https://dev.epicgames.com/documentation/metahuman/metahuman-animator-02-process-and-export-your-animation-in-unreal-engine).
- Epic: the exported result is a standard animation sequence that works like other animation (paraphrase) — VERIFIED (mono doc).
- Hardware: "at least 16 physical, high performance cores with 32GB RAM"; GPU "at least nVIDIA RTX 3070, AMD RX 6800 XT, or Apple M2 Ultra, with 8GB VRAM"; Windows needs DirectX 12 and the default RHI set to DirectX 12; capture resolution/frame rate/duration affect storage and memory — VERIFIED [Hardware Requirements](https://dev.epicgames.com/documentation/metahuman/metahuman-hardware-requirements-in-unreal-engine). This is the general MHA table; no body-specific VRAM figure is published (Gap). The owner's RTX 5080 16 GB exceeds the stated GPU floor; I found no RTX 50-series-specific statement.

### Inferences

## Q7 (Part B). Licence terms for the output (MetaHuman Animator animation, the body plugin, footage/consent, use outside Unreal)

### Takeaway

Open questions for a lawyer: (1) the body plugin's Fab Standard-licence terms and its third-party (SMPL-style) components, and (2) rights in the source video itself (copyright, publicity/privacy, platform terms), which Epic's documents do not address.

## Q8 (Part B). Does Epic's AI MegaJam 2026 say anything about third-party assets, AI-generated animation or footage?

### Takeaway
