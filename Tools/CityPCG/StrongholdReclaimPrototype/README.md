# LAN stronghold reclaim pilot

The proposed pilot has the listen host run the reclaim quest and replicate the gate state to peers. The host campaign's existing quest checkpoint stores the unlock. The prototype implements the cosmetic actor, but has not been compiled or tested. Quest registration, map placement, and LAN verification remain pending.

## Runtime trace

| Path | Current behavior |
| --- | --- |
| `ReflectionsQuestWorldSubsystem.cpp`, `EnsureController`, `GetHero`, `Tick`, `EvaluateObjectives` | `EnsureController` caches the first controller only if it is local. The world ticks its quest evaluation without a server check. `Protect` measures that controller's pawn against the target and adds elapsed time through `AddHeldTime`. Outside time pauses the hold. Host and guest can run independent copies. |
| `ReflectionsVillainSubsystem.cpp`, `HandleSpellHit`, and `ReflectionsVillainPossession.cpp`, `Cleanse` | A world-local spell hit can clear the infection. The native cleanse route calls `SetState(None)` without forwarding the caster. The inspected native path shows no client-to-server delivery or authoritative spell-hit validation. The packaged Blueprint path needs a live check. |
| `ReflectionsNpcSubsystem.cpp`, `SetInfection`, and `ReflectionsQuestWorldSubsystem.cpp`, `HandleNpcInfection` | `SetInfection` broadcasts `OnNpcInfection` locally. The quest listener remembers previously tarnished actors and emits `NpcCured` with the Person ID and location. `NotifyEventAt` can filter by Person ID and horizontal marker radius. It does not establish who cured the character or distinguish upper and lower floors. |
| `ReflectionsQuestSubsystem.cpp`, `FinishStep`, `GiveReward`, `AddUnlock`, `Capture`, `Apply` | The hold step's reward adds the site key to an ordinary `TSet` on a `UGameInstanceSubsystem`. The key is deduplicated locally. `AddUnlock` broadcasts `OnUnlock`. Snapshot apply replaces the set, then broadcasts `OnQuestsChanged`. Reset also broadcasts `OnQuestsChanged`. |
| `ReflectionsGameFlowSubsystem.cpp`, `SetCheckpoint`, `LoadFromSlot`, `OpenMap`, and the quest subsystem's `HandleCheckpointSaved`, `HandleProgressRestored` | The checkpoint save stores the quest snapshot in local `Reflections_Quests` and mirrors those bytes into the checkpoint. A load restores the mirrored files before travel. On progress restoration, the quest subsystem uses the snapshot with matching `SavedAt`. There is no network delivery of these files or unlocks. `OpenMap` calls `OpenLevel` without a listen option, so host reload continuity requires a separate live check. |

## Smallest integration

1. Add this actor pair to the runtime module after the next build slot. Use the three existing stronghold meshes at a single surveyed transform. Assign `GrayLondon_Stronghold_TrinityWatchYard_Reclaimed` to the placed test gate and the hold reward. Keep the three components cosmetic. For this one pilot the actor is always relevant, has no tick or movement replication, and stays awake for restoration in either direction. If the gate is spatially loaded, verify that both the server and a distant guest can load its World Partition cell. For a full city, choose relevancy per site after those measurements.
2. Register the pilot quest on the playable authority world after its network mode is known, using the review-only step example as data. The engine's quest definitions are loaded during game-instance initialization, so perform this pilot registration at world startup and before quest availability or checkpoint application in that world. Leave the pilot definition out of client-local registration. This keeps the existing host-local `Protect` evaluator and quest reward path. Confirm the listen host owns the local quest pawn and the encounter's cure actually occurs in the host world. Resolve one authored capture marker with the exact site name. For a packaged quest, give the site a strict marker lookup using `Find(Name, false)` and require the exact `MarkerName` plus `!bAutoPlaced`. Prefer a stable Person ID for the cure and a height check if a second walkable floor shares the footprint.
3. The actor binds `OnUnlock` and `OnQuestsChanged` on authority and reads `HasUnlock` when it begins play, including stream-in. The host applies visuals immediately. Clients run the same visibility function when they receive the replicated enum. The initial `Pending` state renders the frame alone until the first value arrives, including for a late join. A pre-reclaim restore can turn the flags back to occupied. There is no capture RPC or second save record. [Unreal replicated actor properties](https://dev.epicgames.com/documentation/en-us/unreal-engine/replicate-actor-properties-in-unreal-engine)
4. Persist using an existing host checkpoint or manual save. The current reward path does not itself save. If the design calls for an autosave on capture, schedule it from the authority gameplay layer after the quest transition completes, using `ScheduleCheckpoint` and the existing checkpoint retry path. Restore the host campaign before admitting guests for the save test. The gate can begin play before a cold checkpoint has applied, so startup that accepts guests during restore would need to delay the first state publication until the campaign is ready. Keeping guests connected through checkpoint travel is a separate GameFlow change if the current load ends the session.

## Guest participation

Guests can observe the first pilot. To let them contribute, have the server evaluate the pilot hold against possessed, eligible player pawns in the authored zone. Accumulate once per tick when any eligible pawn is inside. Preserve the existing duration and paused-outside semantics. A guest cure requires the server to execute and confirm the actual spell hit and infected-to-cured transition. If the current cast path only executes on the guest, send a cast request through the guest's owned controller or pawn and run normal server-side spell and hit validation. Keep the quest event local to the authoritative world. If the design needs player credit, carry the validated caster through the transition because existing `NpcCured` does not identify the curer. The same gate actor serves either version.

## Verification after build

Use standalone first, then a listen host and a guest with separate save directories or separate machines. Single-process PIE can make unrelated local save slots look shared. Log net mode, player role, quest step, unlock, received pennant state, and save timestamp at each check. Use an isolated test map before trying the surveyed London site.

| Case | Expected result |
| --- | --- |
| Fresh run | Host and guest see occupied flags. Frame, ground, approach collision, and navigation remain the same before and after reclaim. |
| Host cures the intended person, then holds | A server-world cure advances once. A wrong Person ID or out-of-zone cure does not advance it. Six seconds inside, a pause outside, then six more inside finishes at roughly 12 seconds of accumulated time. Host and guest both show exactly one reclaimed variant. Repeat the cure event and check that the reward stays single. |
| Guest-only changes in host-led pilot | Guest-local Quest console changes, cure, and time inside the zone cannot advance the host quest or change the gate. Compare the host quest state and both visuals. In a later guest-enabled build, assert that one server-confirmed cure counts and duplicate or invalid cast requests do not. Two players holding together still take 12 seconds. |
| Late join, reconnect, and streaming | A new guest sees the correct variant when the gate first replicates, including when the host is away. Travel out of sight or unload the cell, then return. At most the frame alone appears during initialization, and the old variant never flashes. |
| Save and restore | Make an occupied slot, reclaim, save a second slot, and restart the host. Restore the reclaimed slot and reconnect a guest. Repeat for the occupied slot and fresh campaign. Confirm both clients follow the host restored snapshot, even when a guest profile contains the opposite unlock. Also exercise an in-place restore, if available, to cover `OnQuestsChanged` without replaying `OnUnlock`. |
| Missing marker or old save | An unloaded or wrong capture marker provides no progress. A save from before this feature defaults to occupied. Missing or mismatched quest save timestamps follow existing GameFlow behavior and should be logged during the test. |

Use the existing host-side `Quest.Status` and `GameFlow.Checkpoint` commands for inspection and persistence. `Quest.CompleteObjective` can isolate the visual change in a disposable test session. Run a real cure and hold separately to verify the gameplay path. Test the courtyard, both entrances, and both relevant day and night lighting conditions before any live placement.
