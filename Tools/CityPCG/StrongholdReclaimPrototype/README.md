# LAN stronghold reclaim pilot

The proposed pilot has the listen host run the reclaim quest and replicate the gate state to peers. The host campaign's existing quest checkpoint stores the unlock. This is an uncompiled review prototype. Keep the actor outside `Source` until the blockers below are resolved and the integration has a build and LAN test window.

## Runtime trace

| Path | Current behavior |
| --- | --- |
| `ReflectionsQuestWorldSubsystem.cpp`, `EnsureController`, `GetHero`, `Tick`, `EvaluateObjectives` | `EnsureController` caches the first controller only if it is local. The world ticks its quest evaluation without a server check. `Protect` measures that controller's pawn against the target and adds elapsed time through `AddHeldTime`. Outside time pauses the hold. Host and guest can run independent copies. |
| `ReflectionsVillainSubsystem.cpp`, `HandleSpellHit`, and `ReflectionsVillainPossession.cpp`, `Cleanse` | A world-local spell hit can clear the infection. The native cleanse route calls `SetState(None)` without forwarding the caster. The inspected native path shows no client-to-server delivery or authoritative spell-hit validation. The packaged Blueprint path needs a live check. |
| `ReflectionsNpcSubsystem.cpp`, `SetInfection`, and `ReflectionsQuestWorldSubsystem.cpp`, `HandleNpcInfection` | `SetInfection` broadcasts `OnNpcInfection` locally. The quest listener remembers previously tarnished actors and emits `NpcCured` with the Person ID and location. `NotifyEventAt` can filter by Person ID and horizontal marker radius. It does not establish who cured the character or distinguish upper and lower floors. |
| `ReflectionsQuestSubsystem.cpp`, `FinishStep`, `GiveReward`, `AddUnlock`, `Capture`, `Apply` | The hold step's reward adds the site key to an ordinary `TSet` on a `UGameInstanceSubsystem`. | `ReflectionsGameFlowSubsystem.cpp`, `SetCheckpoint`, `LoadFromSlot`, `OpenMap`, and the quest subsystem's `HandleCheckpointSaved`, `HandleProgressRestored` | The checkpoint save stores the quest snapshot in local `Reflections_Quests` and mirrors those bytes into the checkpoint. A load restores the mirrored files before travel. On progress restoration, the quest subsystem uses the snapshot with matching `SavedAt`. ## Blockers before runtime integration

1. **Quest restoration can leave a stale ownership flag.** The draft reads the game-instance unlock in actor `BeginPlay`. GameFlow applies a pending checkpoint later, after a pawn is available. If the quest snapshot is missing or its timestamp differs, `HandleProgressRestored` leaves the existing quests and unlocks in memory and sends no `OnQuestsChanged`. The broader `OnCheckpointRestored` can still broadcast. Keep the host gate in `Pending` until the authority reports a fresh campaign baseline or successfully applies a quest snapshot for the exact selected checkpoint `SavedAt`. Invalidate readiness before another restore. On mismatch, retain `Pending` and surface the error. An intentional legacy migration can publish occupied only after it explicitly resolves the site state for that campaign. The current delegates do not provide this success handshake.
2. **Checkpoint loads can end the listen session.** `LoadFromSlot` calls `OpenMap`, which calls `OpenLevel` with the engine's default absolute travel and empty options. For the first LAN test, restore the host campaign before explicitly starting the listen world and admit or reconnect guests after restoration. Preserving connected guests through checkpoint travel requires a separate host travel path and a network test.
3. **Spatial actor relevance cannot guarantee fresh visual state.** The draft leaves an actor spatially loaded by default. Unreal checks that the connection initialized the actor's level before it considers `bAlwaysRelevant`. A startup actor may also survive a level visibility change with its old enum, and the draft reapplies that value in `BeginPlay`. Make the single replicated pilot actor nonspatial and always loaded on host and guests, with no runtime data layer that can unload it. For spatially loaded sites at city scale, replicate the per-site state on an always-loaded authority object and let the local visual actor read that state each time it streams in. Show the frame alone while the state is unknown. Keep the decorative mesh components nonreplicating so the actor enum is their only networked visibility source.
4. **Fallback or unbound objectives can reclaim the wrong site.** Both the event and hold use marker lookup that can adopt aliases or tagged actors. Even `Find(Name, false)` with the exact `MarkerName` and `!bAutoPlaced` accepts an adopted marker with those values. Resolve exactly one loaded authored marker by reviewed actor identity and owning package for both objectives. Reject a missing, ambiguous, or streamed-out marker without adoption or fallback. Bind the cure event's `arg` to the reviewed encounter's stable Person ID. The current example omits it, so any `NpcCured` inside the 700 cm horizontal radius can advance the quest. Validate vertical separation where another floor falls within the site radius.

## Smallest integration

1. Resolve the blockers and include the actor in a coordinated runtime build. Use the three existing stronghold meshes at a single surveyed transform. Assign `GrayLondon_Stronghold_TrinityWatchYard_Reclaimed` to the placed test gate and the hold reward. Keep the components cosmetic and test both restoration directions with the nonspatial pilot.
2. Register the pilot quest on the playable authority world after its network mode is known, using the review-only step example as data. Make the definition available to the host's snapshot restore, then enable gameplay evaluation after the campaign is ready. Leave the pilot definition out of client-local registration. Confirm the listen host owns the local quest pawn and the reviewed Person's cure occurs in the host world. Use the same authored marker identity in the cure and hold validators.
3. Bind `OnUnlock` and `OnQuestsChanged` on authority for changes after readiness. The host applies that validated state locally. Clients run the same visibility function when they receive the replicated enum. Keep `Pending` frame-only until authoritative state arrives, including for late join. A successful pre-reclaim restore can publish occupied again. The existing checkpoint remains the sole persistence path. [Unreal replicated actor properties](https://dev.epicgames.com/documentation/en-us/unreal-engine/replicate-actor-properties-in-unreal-engine)
4. Persist using an existing host checkpoint or manual save. The reward path does not itself save. For an autosave on capture, schedule it from the authority gameplay layer after the quest transition completes, using `ScheduleCheckpoint` and the existing checkpoint retry path. Confirm the mirrored quest snapshot timestamp matches the selected host checkpoint.

## Guest participation

Guests can observe the first pilot. To let them contribute, have the server evaluate the pilot hold against possessed, eligible player pawns in the authored zone. Accumulate once per tick when any eligible pawn is inside. Preserve the existing duration and paused-outside semantics. A guest cure requires the server to execute and confirm the actual spell hit and infected-to-cured transition. If the current cast path only executes on the guest, send a cast request through the guest's owned controller or pawn and run normal server-side spell and hit validation. Keep the quest event local to the authoritative world. If the design needs player credit, carry the validated caster through the transition because existing `NpcCured` does not identify the curer. The same gate actor serves either version.

## Verification after build

Use standalone first, then a listen host and a guest with separate save directories or separate machines. Single-process PIE can make unrelated local save slots look shared. Log net mode, player role, quest step, unlock, received pennant state, and save timestamp at each check. Use an isolated test map before trying the surveyed London site.

| Case | Expected result |
| --- | --- |
| Fresh run | Host and guest see occupied flags. Frame, ground, approach collision, and navigation remain the same before and after reclaim. |
| Host cures the intended person, then holds | A server-world cure advances once. A wrong Person ID or out-of-zone cure does not advance it. Six seconds inside, a pause outside, then six more inside finishes at roughly 12 seconds of accumulated time. Host and guest both show exactly one reclaimed variant. Repeat the cure event and check that the reward stays single. |
| Guest-only changes in host-led pilot | Guest-local Quest console changes, cure, and time inside the zone cannot advance the host quest or change the gate. Compare the host quest state and both visuals. In a later guest-enabled build, assert that one server-confirmed cure counts and duplicate or invalid cast requests do not. Two players holding together still take 12 seconds. |
| Late join, reconnect, and streaming | A new guest sees the correct variant when the gate first replicates, including when the host is away. Travel out of sight or unload the cell, then return. At most the frame alone appears during initialization, and the old variant never flashes. |
| Save and restore | Make an occupied slot, reclaim, save a second slot, and restart the host. Restore the reclaimed slot and reconnect a guest. Repeat for the occupied slot and fresh campaign. Confirm both clients follow the host restored snapshot, even when a guest profile contains the opposite unlock. Also exercise an in-place restore, if available, to cover `OnQuestsChanged` without replaying `OnUnlock`. |
| Missing marker or old save | An unloaded, duplicated, adopted, or wrong capture marker provides no progress. Verify the explicit migration result for an older campaign. Missing or mismatched quest data keeps the gate pending and logs the restore failure. |

Use the existing host-side `Quest.Status` and `GameFlow.Checkpoint` commands for inspection and persistence. `Quest.CompleteObjective` can isolate the visual change in a disposable test session. Run a real cure and hold separately to verify the gameplay path. Test the courtyard, both entrances, and both relevant day and night lighting conditions before any live placement.
